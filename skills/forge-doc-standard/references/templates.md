# 文档结构

按读者任务选结构，标题与篇幅可以调整。以下是组织方式，不是每页必须复制的骨架。

## 组件文档

1. 一句话说明组件能完成的主要任务。
2. 最小可用示例，保留关键配置区和自定义插槽的简短注释。
3. 常见扩展：权限、异步数据、自定义操作、样式或平台限制。
4. Props、事件、插槽与公开方法；复杂组件可拆子页并提供索引。

组件名、绑定值和 Props 以源码为准。例如当前上传组件的完整基础示例：

```vue
<template>
  <SingleImageUpload v-model="avatarUrl" :max-file-size="2" accept="image/*" />
</template>

<script setup lang="ts">
import { ref } from "vue";
import SingleImageUpload from "@/components/Upload/SingleImageUpload.vue";

const avatarUrl = ref("");
</script>
```

不要再生成旧的通用 `Upload` 组件或不存在的 `maxSize`、存储类型 Props。

CRUD 首页使用真实用户 API 和少量字段；表单与列表配置名称以当前类型为准。展示扩展点时明确标记：

```vue
<!-- 自定义单元格插槽 -->
<template #table-cell-status="{ row }">
  <el-tag :type="row.status === 1 ? 'success' : 'info'">
    {{ row.status === 1 ? "启用" : "禁用" }}
  </el-tag>
</template>
```

这是 `CrudPage` 内的插槽片段，完整上下文由所在页面提供。正文解释插槽参数和需要保留的行为，不再复述“其他列照常渲染”。

## Composable 文档

依次说明最小调用、参数、返回状态与动作。类型定义仅在不能用参数表清楚表达时展开；完整调用复用真实函数，不自造返回字段。

例如 `usePageTable` 需要说明：

- `handleQuery` 搜索第一页，`fetchData` 刷新当前页。
- 查询、总数、列表和 loading 的实际返回类型。
- 请求异常由谁处理，过期响应如何失效。
- 选择状态和表单提交由调用方管理。

实时功能使用当前 WebSocket 接口，不再生成已删除的 `useSse`、`useDictSync`。参数与返回值先读 `src/composables/useRealtime.ts`，不能根据旧文档推断。

## 开发教程与规范

教程按“准备条件 → 最小实现 → 验证”组织，读者能看出需要修改哪些文件。只解释完成当前任务所需的概念。

规范按命名、类型、状态、注释等维度组织。每条给出可执行的约定；容易误解时加一个短例子，并标明是框架机制、社区惯例还是项目选择。

新增 API 与查询时用 `UserQuery`、`PageQuery`，后端保留 Form、Query、DTO、VO 的职责区分。不要将前后端强制成同一套后缀。

## 操作与部署指南

开头写适用前提与完成效果，正文按实际步骤组织。涉及配置时写明文件和字段，涉及移除时写清边界与依赖，最后给出可执行的验证。

- 菜单、权限和路由示例按当前项目核对，不复制其他管理框架的菜单类型值。
- 页面缓存按当前 fullPath 包装机制说明，不声称必须与固定组件 name 一致。
- Nginx 的代理前缀与环境文件保持一致；实时路径按当前 WebSocket 配置处理。
- 发布、迁移或删除要明确环境与影响；示例命令不能代替目标环境确认。

## 问题排查

以症状为标题，先给排查入口与解决步骤，再补必要原因。涉及版本时注明适用范围，不能将旧兼容参数作为当前默认方案。

复用已有 FAQ；局部使用限制也可以紧邻相关示例，不必为每条注意事项新建 FAQ。
