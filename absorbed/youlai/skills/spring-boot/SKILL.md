# Spring Boot 后端开发

依据真实代码完成后端开发、审查和重构。下列命名、分包与注释格式是 参考实现 的项目约定；其他仓库沿用其既有契约。

## 开始前

1. 阅读仓库指令、`pom.xml`、目标模块、相关配置和未提交改动。
2. 核对前端调用、数据库约束与已有测试，确认请求、响应和失败语义。
3. 复用已有能力；仅在任务需要时调整公共契约、依赖或包边界。

依赖版本与兼容基线以 `pom.xml` 为准，不从 Skill 的示例推断版本，也不随功能开发自动升级依赖。

## 核心约定

- 保留 `Form / Query / DTO / VO` 分类。查询条件用 `UserQuery`，参数名用 `query`；不要增加无实际区别的 `QueryParams`、`PageQuery` 副本。
- 更新目标以路径 ID 为准；新增不能因请求体含 ID 而执行更新。嵌套资源同时校验父子归属。
- Controller 适配 HTTP；Service 承担授权范围、状态与事务规则；Mapper 处理持久化。Entity 不作为对外响应。
- 权限采用 `模块:资源:操作`，沿用同类模块的动作；入口权限不能替代资源归属和数据范围检查。
- `common` 不反向依赖基础设施或业务域；`framework` 通过已有端口获取业务能力。业务域之间避免循环依赖和 Entity 泄漏。
- 类、接口、枚举、record 和业务方法使用展开的多行 Javadoc。摘要说明职责；实现原因写就近的 `//`，不翻译代码。
- 模板优先保持直接、可读的实现；不为每个类配接口，也不为形式拆 DTO、Facade、事件或微服务。刷新竞争、事务提交和监听清理等行为保障仍须保留。

## 完成前

- 同步受影响的调用方、代码生成模板和使用文档；历史审查记录可以保留当时命名。
- 编译并运行与行为变化相关的测试。认证、并发、权限、路径 ID 和事务改动应验证对应边界。
- 使用仓库已有的检查工具，不在本次任务中另建一套格式规范或 CI。
- 报告实际验证结果与未覆盖部分。外部数据库、Redis 或认证中心不可用时，不能将替身测试描述为集成验证。
