# 注释与 Javadoc

本文件规定 参考实现 的注释格式。多行排版、中文说明及标签取舍属于项目约定，不冒充所有 Java 项目的通用规则。

## 格式

| 成员                                                 | 形式                                   |
| ---------------------------------------------------- | -------------------------------------- |
| 类、接口、枚举、record、注解类型                     | 多行 Javadoc                           |
| 业务方法，包括私有业务方法                           | 多行 Javadoc                           |
| 接口实现与重写方法                                   | 可继承已有契约；新增约束写多行 Javadoc |
| 字段与枚举值                                         | 需要时用 `//`；已有 Schema 不重复描述  |
| 实现原因、事务与并发边界                             | 相关语句上方的 `//`                    |
| 普通 getter/setter、纯装配构造器、测试方法、匿名回调 | 不机械添加文档                         |

类和方法的 `/**`、正文与 `*/` 各占一行，即使正文只有一句。禁止将类、接口、record 或方法写成 `/** 一句话 */`。

```java
/**
 * 保存已验证的会话身份及访问凭证期限。
 *
 * @since 4.12.0
 */
public record AuthenticatedSession(...) {
}

/**
 * 轮换刷新凭证并重新加载账号权限。
 */
public TokenPair refresh(String refreshToken) {
    ...
}
```

## 内容

- 类写职责，方法写动作和对象；先改好命名，不靠长注释解释含糊名称。
- 摘要一行即可。有真实的参数限制、特殊结果或调用约束时再补充，不写实现流水。
- 不逐行翻译代码，不堆叠“统一、集中、唯一入口、权威状态”等修饰。
- 方法内部需要说明事务、并发或清理原因时，用就近的短行注释。
- 完整状态机、流程、例子、迁移说明放在项目 `docs`。
- 修改代码后核对注释；过时的结论不能因原先有文档而保留。

```java
// 事务回滚时不发布可用会话。
afterCommit(() -> publishSession(session));

// 只归还当前任务的预算，避免迟到回调影响新任务。
releaseBudget(task);
```

## 标签

- `@param`：说明类型没有表达的格式、单位、范围或空值语义。
- `@return`：说明特殊返回值；void 方法不写，禁止空标签。
- `@throws`：只列调用方需要处理的失败条件，不罗列所有内部异常。
- `@since`：记录首次引入版本，不随项目版本升级修改历史标签。
- `@author`：保留已有署名，不自创或替维护者署名。
- `{@link}`：用于已存在的关联类型，不将所有名词都做成链接。
- `@deprecated`：与 @Deprecated 配合，写出实际替代方法。

不强制使用 `{@summary}`。已有 @Operation、@Schema 时，避免再复制整段协议说明；需要方法摘要时保持简短。

## 自查

1. 类、方法文档是否展开多行，且摘要与实际职责一致？
2. 是否缺少业务方法说明，或把方法文档写成了行注释？
3. 是否保留了必要的事务、并发和清理原因？
4. 是否出现空标签、重复 Schema、失真的 @since 或伪造作者？
5. 是否混入装饰线、注释掉的实现、真实密码或令牌？

语法参考：[Oracle Javadoc](https://docs.oracle.com/en/java/javase/17/docs/specs/javadoc/doc-comment-spec.html)。内容与排版参考 [Alibaba 注释规约](https://github.com/alibaba/p3c/blob/master/p3c-gitbook/编程规约/注释规约.md) 和 [Google Java Style](https://google.github.io/styleguide/javaguide.html#s7-javadoc)。两者的覆盖范围与标签取舍不同，以本项目明确的多行要求为准，不混称为社区统一强制规则。
