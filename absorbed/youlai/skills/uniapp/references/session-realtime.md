# 会话与实时连接

修改登录、请求封装或实时连接时读取。先核对 `src/store`、`src/utils/request.ts`、`src/utils/auth.ts` 与现有实时协议，复用已存在的责任边界。

## 会话

- Store 是响应式登录状态的唯一入口；凭证写入和退出同时更新内存与持久化。
- 并发失效请求共用同一续期 Promise，成功后各自重试一次；续期接口不进入自身的重试链。
- 登录、退出、切换账号推进会话版本；请求与续期回填前检查版本，旧账号结果不能覆盖新账号。
- 明确凭证失效才清理登录态；网络故障、超时、服务端暂时异常保留会话并返回错误。
- 请求封装统一解包、错误类型和续期；提示与导航只有一个责任方，避免页面和拦截器重复跳转。
- 密码、验证码不持久化；访问令牌和刷新令牌按会话策略保存，不能用“敏感数据不存储”误删必要机制。
- 后端令牌模式与 OIDC 是不同层次；客户端使用返回的访问凭证，不自行解析 JWT 推断权限或认证有效性。

## 实时连接

沿用下列职责，不再增加与它们重复的 `services` 或独立连接 Store：

| 位置                         | 职责                                   |
| ---------------------------- | -------------------------------------- |
| `api/realtime.ts`            | HTTP 领票接口                          |
| `utils/realtime/client.ts`   | SocketTask、连接状态、心跳、重连和释放 |
| `utils/realtime/protocol.ts` | 消息类型与运行时解析                   |
| `composables/useRealtime.ts` | 应用生命周期和业务刷新信号             |

- 应用拥有一个有效连接；页面只订阅信号并在销毁时取消订阅，不各自新建连接。
- 使用 `uni.connectSocket` 返回的 `SocketTask` 管理当前连接，避免全局 Socket API 交叉操作其他连接。保留 `success/fail/complete` 中至少一个回调，避免返回 Promise；同时核对安装版本的行为。
- 主题随领票请求提交，收到服务端 `ready` 后进入业务可用状态。
- 连接尝试通过对象身份或序号隔离迟到回调；失败入口统一清理连接、心跳与超时任务，再决定是否重连。
- 重连采用有上限的退避与随机延迟；同一时刻只保留一个重连任务。认证或协议拒绝不能立即无限重试。
- 每次建连重新领票；凭证到期由服务端关闭连接。票据不持久化，不输出含票据的 URL。
- 对外部消息先解析和校验，再分发给业务。实时变更提示配合 HTTP 补拉，断线恢复后校准，不能把推送视为永久可靠的数据源。

业务校准复用各资源 API，例如通知查询，不在 `RealtimeAPI` 中臆造重复接口。通知列表、公告数量和未读数含义不同，使用计数前核对筛选与范围；现有页面未实现的能力不能只靠类型或文档宣称支持。

## 平台生命周期

- uni-app 页面可能缓存；组件卸载、页面隐藏、应用进入后台是不同事件，不能只依赖 `onUnmounted`。
- 本项目小程序进入后台释放连接，回到前台重新领票并校准；H5 隐藏页面时保留连接、暂停定期校准。这是项目策略，不能当作所有平台的强制机制。
- H5 的 DOM、`visibilitychange` 与浏览器网络事件放在对应条件编译内；小程序使用应用生命周期和 `uni` 网络监听。
- 释放监听时使用原处理器引用；退出、销毁、热更新也应清理计时器与订阅。
- H5 验证代理与 HTTPS/WSS；小程序另验证合法域名、真机前后台和断网恢复。浏览器构建通过不能代替小程序验收。
