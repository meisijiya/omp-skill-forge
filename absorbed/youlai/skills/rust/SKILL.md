# Rust 后端开发

依据当前仓库的技术栈与既有契约完成后端开发、审查与重构。下列约定用于约束新增代码；仓库已有规则优先。

## 开始前

- 读取 `Cargo.toml`、`src/main.rs` 与相关模块，确认实际依赖版本与分层方式。
- 查看 Git 状态，保留未提交改动，不顺手重构无关代码。
- 按任务从下表读取对应参考，不一次性加载全部文件。

## 核心约定

- Entity 由 `sea-orm-cli` 生成后不手工改字段定义，VO 转换单独实现。
- 错误统一转换为 `AppError`，Handler 返回 `Result`，不在业务代码里拼装错误响应。
- 成功响应统一包装，异常保留正确 HTTP 状态，业务码只用于补充语义。
- 路由注册时固定路径必须排在动态路径之前。
- 多表写入使用事务，批量操作避免逐行查询。
- doc comment 说明不变量、错误条件与生命周期约束，不复述类型签名。

## 完成前

- 运行项目原生的格式化、静态检查与测试命令，如实报告失败与未覆盖项。
- 新增接口保持与现有响应结构、错误码和权限标识一致。
- 不通过放宽类型、跳过校验或删除断言掩盖失败。
- 说明修改内容、验证结果与剩余风险。
