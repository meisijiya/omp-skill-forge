# Laravel 后端开发

依据当前仓库的技术栈与既有契约完成后端开发、审查与重构。下列约定用于约束新增代码；仓库已有规则优先。

## 开始前

- 读取 `composer.json`、路由文件、基础模型与相关模块，确认实际依赖版本与分层方式。
- 查看 Git 状态，保留未提交改动，不顺手重构无关代码。
- 按任务从下表读取对应参考，不一次性加载全部文件。

## 核心约定

- 模型继承项目基础模型，通过 Eloquent 完成查询，字段映射与逻辑删除沿用基类约定。
- 控制器只做请求适配，业务规则放在 Service，入参校验交给独立的 Validate。
- 成功响应统一包装，业务异常通过 ResultCode 枚举抛出并保留正确 HTTP 状态。
- 响应字段按项目约定做驼峰转换，前端拿到的键名与接口契约一致。
- 多表写入使用事务；多租户作用域在查询入口统一施加，不依赖逐条手工过滤。
- PHPDoc 说明业务约束与非显然副作用，不复述方法名。

## 完成前

- 运行项目原生的格式化、静态检查与测试命令，如实报告失败与未覆盖项。
- 新增接口保持与现有响应结构、错误码和权限标识一致。
- 不通过放宽类型、跳过校验或删除断言掩盖失败。
- 说明修改内容、验证结果与剩余风险。
