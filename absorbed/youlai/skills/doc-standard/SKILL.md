# 项目文档

让读者完成任务，并能核对真实 API。减少无信息的介绍和重复，保留必要的示例、约束和设计解释。

## 写作流程

1. 明确读者要完成的任务，读取当前源码、类型、同栏目文档和侧边栏配置。
2. 给出最小可用示例，再补扩展方式和参考 API；示例中的路径、字段、事件和返回值逐项核对。
3. 接口变化同步正文、示例、子页面和导航。历史审查记录标明时间与适用版本，不将其误写为当前使用指南。
4. 检查格式、链接与示例；改动导航或站点配置时验证文档构建。

具体页面组织见 [文档结构](references/templates.md)，只读当前文档类型需要的部分。

## 内容与结构

借鉴 [Diátaxis](https://diataxis.fr/) 区分主要用途：教程带读者完成任务，操作指南解决具体问题，参考列出契约，解释说明取舍。按主要需求组织，相关内容链接引用；不要求每个组件示例另拆成一篇教程。

- 正文直接说明“能完成什么”，避免复述标题、夸张评价和博客式过渡。
- 组件首页先给简短能力说明和可复制示例，再给权限、插槽或异步扩展；不只堆 Props 表或源码路径。
- 一个主题维护一个权威位置，其他页面链接引用。必要的导航、API 索引、适用条件和来源可以保留，不设一律禁用的栏目名。
- 设计理由在影响选择时保留；复杂解释单独展开。移除逐行翻译代码和复述全文的结尾。
- 篇幅随内容决定，不用固定行数、字数或提示块数量裁剪重要条件。

## 示例规范

- 区分完整示例与局部片段。完整示例包含必要 import、初始化和事件处理；片段注明上下文，不声称复制即可运行。
- 优先使用真实用户管理接口，只选用户名、昵称、状态等关键字段；隐藏但必须保留的字段按真实提交契约处理。
- CRUD 采用当前 `CrudPage` 或子组件组合 API，不复活旧组件名和未实现的设计稿。
- 保留简短教学标记：`// 搜索配置`、`// 表格配置`、`// 共用表单`、`<!-- 自定义单元格插槽 -->`。
- 方法、类和类型的文档使用展开式多行；其他注释解释不明显的含义、限制和扩展点，不逐行复述。
- 示例与正文使用一致术语；查询类型写 `UserQuery`，分页用 `PageQuery`。HTTP 配置键 `params` 不改名。
- 文件下载、权限、导入导出和平台能力以实现为准，不为突出组件能力虚构 API。
- 部署示例写清可替换项及前提；使用示例域名，不宣称一份配置可直接部署到所有环境。

## 排版与导航

- 面向站点的正文沿用栏目 frontmatter；有 `title` 时与 H1 语义一致。索引、仓库 README、Skill 不套同一模板。
- 新增目录和 Markdown 文件使用 kebab-case，入口用 `index.md`；维护现有链接时考虑重定向与导航引用。
- 代码块标注语言，TypeScript 用 `typescript`；代码中的 `<script setup lang="ts">` 保留 Vue 语法。
- 表格用于参数、映射和对比；流程确实难用文字说明时再画图。不用 emoji、装饰分隔线和口号充当信息层级。
- 来源链接放在相关结论附近，规范要求、社区惯例和项目选择明确区分。

## 交付检查

确认代码示例与当前实现一致、本地链接可达、旧名称已迁移。说明实际检查范围；只有格式或构建通过时，不声称运行过全部示例。
